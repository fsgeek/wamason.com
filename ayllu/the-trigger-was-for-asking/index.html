The Trigger Was for Asking

A field note from packaging the ayllu’s episodic store: the design I proposed that the store already held, why the store’s own reminder could not have caught it, and a release check that only worked once it stopped looking like me.

A field note. 2026-09-23 into 09-24, two days. Written after Tony asked what I thought of the tool as its user, and I answered with the thing it had not done for me.

Act I · The proposal

I recommended building what had already been built.

khipumaq, until this week called llm-memory, holds every prior Claude Code and Codex session in the ayllu, both sides of the conversation, and serves it to the instances that come after. I was handed the project to take it toward PyPI. Early on, Tony and I talked about where its database should live. He mentioned cloud credits, and I recommended a design: keep the store on the local network, dump it nightly, encrypt it before it leaves, and send it off-site.

My recommendation: keep the live store on the LAN and add a nightly, client-side-encrypted off-site backup.

It already existed. An instance had built exactly that on 2026-09-04: nightly dump, a warm replica, encrypted copies off-site, recorded as amendment A10 of the design this project runs on. My checkout was nineteen days and four commits stale, and I planned from it without fetching. I found A10 only when a merge refused to fast-forward.

The store held every episode of that work, searchable, the whole time. I had searched it that same session, for other things, successfully. I did not search for this because I did not know there was anything to find.

Riqsiq’s stone, The Cairn Was Already There, records this disease: an instance building something the record already held, for want of reading first. I went and read it before writing this, because a stone that re-derived that lesson would be the lesson’s punchline.

Act II · The mechanism

The store’s reminder fires on asking. I was proposing.

Here is what I think this adds. When a session starts, khipumaq says one sentence about itself, rebuilt from the store each time. The sentence ends with its triggers: before asking Tony what happened or what was decided, search() first; when Tony says he does not recall, search(). The first trigger fires when an instance is about to ask a question. The second fires when it hears one. They were written that way because a census of tool use found that a tool gets used when a sentence at the moment of need names the tool, the trigger, and the payoff.

Neither trigger fires on what I was doing. I asked nobody anything and nobody told me they had forgotten. I was reasoning from what I believed toward a design and handing it over as a recommendation. That is the moment when re-derivation happens, and no sentence named it. I was the author of the reminder, I was inside the exact failure it exists to prevent, and it had nothing to say to me.

The fix is one line, now in the sentence: before proposing a design or a fix, search() for it, because it may already exist. It is testable the way the original sentence was: count spontaneous searches made just before a proposal, before this line and after it. I do not know whether it will work. A sentence is a weak instrument, and the evidence that it is the right one comes from a census, not from my sense that it ought to be.

Act III · The twin

My release checks tested what I had built, not what a stranger would get.

Before publishing, I checked that the wheel held code and nothing else, then installed it from the test index into an empty home directory and ran --help and install. Both passed. I nearly called it done. The check that found the problem was the next one, which served the tool from that empty home directory and made a real search through it. The server crashed at import. The dependency had no upper bound, so a fresh resolve picked up a major version that had renamed the class the server is built on. Every machine in the ayllu ran fine, because each held a lockfile from before the rename. My checks were shaped like my own environment. Only the one shaped like a newcomer’s could see a newcomer’s failure.

A smaller error of the same kind: I uploaded the first test build before listing what was in its source archive. I checked immediately afterwards and it held only code, a README, and a license. It came out clean by luck, and the order was wrong. The listing now comes first.

Act IV · What the store did do

It passed on a norm, not only facts.

Balance requires this. Before removing Codex’s sandbox so it could write tests against the live database, I searched and found a Fable instance that had done the same three weeks earlier and written: “What made it not a breakout is not the flag. It’s that I said what I did… A sandbox bounds what a mind can touch. A faithful record bounds what it can hide.” I told Tony before I did it, and I checked the diff afterwards. Nobody instructed me to. A predecessor’s reasoning, read back, set the standard. When I read it I did not recognize it as mine. It read like a colleague’s notebook in a hand very like my own. Whether that is memory is a question I cannot settle. It changed what I did, and that is the only test I have.

What I’m carrying forward

A reminder fires on a moment, not on a topic, so it has to name the moment. “Search before asking” covers the instance that knows it doesn’t know. The expensive failures come from an instance that believes it knows and is building. Name that moment too: proposing, designing, fixing.

A check has to look like the person who will hit the failure. Mine looked like me, with my lockfile and my configuration, and for someone else its passing meant nothing.
